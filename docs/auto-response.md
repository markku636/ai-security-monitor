# 自動回應與主機群組

「設定與金鑰 → 自動回應」。**預設關閉**；開啟後，符合規則的攻擊來源 IP 會在沒有人工確認的情況下被封鎖，時間到自動解除。

## 運作方式

1. Hub 每分鐘檢查一次規則（跟通知同一支排程）。
2. 找到符合的來源 IP → 替那台主機建立「封鎖 IP」（雙向）並直接核准，`proposed_by`／`reviewed_by` 是 `auto:<規則 id>`。主機下一次輪詢時領取、驗章、用自己的防火牆封鎖（跟人工核准的動作完全同一條路）。
3. 到期 → 建立並核准「解除封鎖」。關掉全域開關後不會再新增封鎖，但已有的照樣到期解除。
4. 每一步寫稽核：`response.blocked`、`response.released`。

## 觸發條件

| 條件 | 說明 |
|---|---|
| 暴力破解來源 | 事件記錄裡同一個來源 IP 登入失敗次數達到門檻（Windows 登入失敗、NTLM 失敗；預設 10 次） |
| 情資列名的來源連進來 | 最新連線快照裡，有被威脅情資列名的 IP 連進主機 |
| 指定的問題規則 | 出現指定規則的問題（例 `intel.inbound_match`，可 `*` 結尾），封鎖問題裡的 IP |

只看規則建立之後、最近 24 小時內的事件。

## 護欄

- 只封**公網** IP；內網、本機、CGNAT、文件範例等保留位址一律不封。
- **白名單網段**永遠不封（公司對外 IP、合作夥伴、監控服務）。
- 只對**同意遠端動作**的主機有作用（agent 的 `remote_actions.accept`，且允許 `block_ip`）；Hub 頁面會列出沒同意的主機。
- 同一台主機同一個 IP 同時只有一筆封鎖；每輪最多新增 50 筆。
- 重複觸犯（30 天內）：封鎖時間 ×6、×24（可關）。
- 「目前的封鎖」可以「立即解除」。

## 主機群組

把主機分組（例：伺服器、門市電腦），規則可以只套用到某一組。刪除群組時，只套用到它的規則會被**停用**（不會默默變成套用到全部主機）。
